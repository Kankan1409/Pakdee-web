- **ปัญหา:** กดออกบิลได้ทั้งที่ยังไม่บันทึกมิเตอร์ (ระบบไปใช้เลขมิเตอร์ของเดือนอื่นแทน หรือคิดค่าน้ำ-ไฟเป็น 0) และกดซ้ำแล้วบิลเดิมถูกคำนวณทับ ถ้าบิลจ่ายแล้วจะได้บิลใหม่ซ้ำแบบ `INV-YYYYMM-ห้อง-xxxx`
- **แก้ (`src/app/page.tsx` → `handleGenerateMonthlyInvoices`):** เพิ่มเงื่อนไขก่อนสร้างบิลของแต่ละห้อง
  - ห้องที่มีบิลรอบเดือนนี้อยู่แล้ว (`INV-YYYYMM-ห้อง` หรือ `INV-YYYYMM-ห้อง-xxxx` ที่ไม่ได้ยกเลิก) → ข้าม
  - ห้องที่ยังไม่มีเลขมิเตอร์ของรอบเดือนนี้ (`billing_month` ตรงกับเดือนที่ออกบิล) → ข้าม ไม่ใช้เลขของเดือนอื่นแทนแล้ว
  - toast สรุปว่าออกได้กี่ใบ และข้ามห้องไหนเพราะอะไร ถ้าออกไม่ได้เลยจะเตือนให้ไปบันทึกมิเตอร์ก่อน
- **เพิ่มเติม (ตามที่ผู้ใช้ขอ: ต้องกดบันทึกมิเตอร์ก่อนถึงจะคำนวณได้):**

    - ยังไม่มีห้องไหนที่กดบันทึกมิเตอร์ของรอบเดือนนี้และยังไม่มีบิล → "กรุณากดบันทึกมิเตอร์น้ำ-ไฟของรอบเดือน YYYY-MM ก่อน"

- **สาเหตุที่น่าจะเป็น:** ข้อมูลในเบราว์เซอร์มี id ซ้ำกันในการบันทึกรอบเดียว Postgres จึงปฏิเสธทั้งชุด ยังยืนยันไม่ได้ เพราะไม่ได้รับอนุญาตให้ทดสอบเขียนข้อมูลจริง
- **แก้:** `safeUpsert` ใน `supabase-relational.ts`
  - ตัดแถวที่ id ซ้ำกันออกก่อนบันทึก (`dedupeRows`)
  - ถ้าบันทึกไม่สำเร็จ จะแสดง `[Supabase Relational] Upsert <ตาราง> failed: ...` ใน Console จากเดิมที่ล้มเหลวเงียบๆ
- error 400 ที่เกิดจากคอลัมน์ `owner_id`, `owner_phone` หรือ `lease_end_date` ยังไม่มีในตาราง เป็นเรื่องปกติ ระบบจะตัดคอลัมน์นั้นออกแล้วลองส่งใหม่เอง

### 🟡 เครื่องอื่นไม่รีเฟรชเองเมื่อข้อมูลเปลี่ยน
- **สาเหตุ:** Supabase เปิด Realtime ไว้แค่ตาราง `pakdee_store` ตัวเก่าที่เลิกใช้แล้ว ตารางที่ใช้จริงไม่ส่งแจ้งเตือน
- **แก้:**
  - เพิ่มไฟล์ `docs/supabase_realtime_relational.sql` ⏳ ต้องเอาไปรันใน Supabase
  - `page.tsx`: ถ้ามีแจ้งเตือนเข้ามาหลายรายการติดกัน จะรวบเป็นการโหลดใหม่ครั้งเดียว (รอ 800 ms) และจะโหลดข้อมูลใหม่ทุกครั้งที่กลับมาที่แท็บหรือหน้าต่าง

### 🟡 เพิ่มสาขาแล้วต้องรีเฟรชหน้าเอง
- **แก้:**
  - `database.service.ts`: เพิ่ม `refreshFromServer()` ส่งการเปลี่ยนแปลงที่ค้างอยู่ขึ้น Supabase ทันที (`flushRelationalSync`) แล้วโหลดข้อมูลใหม่จาก Supabase
  - `page.tsx`: เรียก `refreshFromServer()` หลังสร้างสาขา
- **ข้อจำกัด:** ถ้าเน็ตหลุดตอนบันทึก สาขาใหม่จะหายไปจากหน้าจอ

### 🟡 ใช้งาน 2 เครื่องแล้วสาขาสลับไปมา
- **สาเหตุ:**
  1. รหัสสาขาใหม่คำนวณจากรายการในเครื่องตัวเอง ถ้าสองเครื่องสร้างสาขาใกล้ๆ กัน จะได้ P000x ซ้ำกันแล้วบันทึกทับกัน
  2. ตอน sync ระบบลบสาขาใน Supabase ที่ไม่มีในเครื่องตัวเอง สาขาที่อีกเครื่องเพิ่งสร้างจึงโดนลบ
  3. ตาราง `properties` ไม่มีคอลัมน์เจ้าของ ทุกบัญชีเลยเห็นทุกสาขา
- **แก้:**
  - `createBranch`: เช็กรหัสสาขาที่มีอยู่แล้วใน Supabase ก่อนออกรหัสใหม่
  - เลิกลบสาขาอัตโนมัติตอน sync สาขาจะถูกลบก็ต่อเมื่อกดลบเองเท่านั้น
  - บันทึกและโหลด `owner_id`/`owner_phone` ของสาขา ⏳ ต้องรัน SQL เพิ่มคอลัมน์ก่อน

### 🟡 ลบสาขาแล้วข้อมูลค้างในฐานข้อมูล
- **สาเหตุ:** โค้ดลบแค่แถวใน `properties` แต่ foreign key ในฐานข้อมูลจริงตั้งไว้ให้ทำเป็น NULL แทนที่จะลบตาม แถวลูกจึงค้างอยู่โดยมี `property_id` เป็น NULL
- **แก้:** เพิ่ม `deletePropertiesCascade()` ใน `supabase-relational.ts` ลบ `invoices`, `contracts`, `repairs`, `expenses`, `rooms`, `buildings`, `branch_settings` ของสาขานั้นเองโดยตรง แล้วค่อยลบ `properties` ใช้ใน `deleteBranch`

### 🟡 บิลไม่ผูกกับผู้เช่า (`invoices.tenant_id` เป็น NULL)
- **สาเหตุ:**
  1. `createInvoice` ไม่ได้บันทึก `tenantId` ลงในบิล ตอน sync จึงต้องผูกผู้เช่าจากชื่อในบิลอย่างเดียว
  2. ผู้เช่าที่ย้ายออกถูกลบออกจากตาราง `tenants` ตอน sync และเพราะ foreign key เป็น `ON DELETE SET NULL` บิลค้างชำระของเขาจึงไม่รู้ว่าใครเป็นคนค้าง
- **แก้:**
  - `createInvoice` บันทึก `tenantId` ลงในบิลแล้ว
  - ตอน sync บิล หาผู้เช่าตามลำดับ: `tenantId` ที่บันทึกไว้ → ชื่อในบิล (เลือกคนห้องเดียวกันก่อน) → ผู้เช่าปัจจุบันของห้อง
  - `pruneOrphanRows`: ไม่ลบผู้เช่าที่ยังมีบิลผูกอยู่ เก็บไว้เป็นประวัติ
