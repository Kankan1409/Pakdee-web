- **ผู้ใช้แจ้ง:** สร้างสาขาใหม่ (P0002 "หอมดี") เพิ่มห้อง เพิ่มผู้เช่าได้ แต่สร้างบิลแล้วบิลหาย · อยากให้ข้อมูลแต่ละสาขาแยกกันไม่ซ้ำกัน · ขอลบตาราง buildings

- **สาเหตุที่ข้อมูลหาย:** `pruneOrphanRows` ลบทุกแถวในตารางที่ "ไม่มีในรายการของเครื่องที่กำลังบันทึก" แบบไม่ดูสาขา และทำงานฝั่งเซิร์ฟเวอร์ด้วย — เส้นทางฝั่งเซิร์ฟเวอร์ (ส่งบิลเข้า LINE, webhook, แจ้งเตือนอัตโนมัติ) โหลดข้อมูลของตัวเองซึ่งอาจเก่ากว่าที่เบราว์เซอร์เพิ่งบันทึก (เช่น ออกบิลแล้วระบบส่ง LINE ทันที) พอเซิร์ฟเวอร์บันทึกรายการบิล ก็ลบบิลใหม่ที่ไม่มีในข้อมูลของมันทิ้ง · และ `syncTenantsToSupabase` ลบผู้เช่าทุกครั้งที่บันทึกห้องด้วย
- **สาเหตุที่สาขาปนกัน:** ผู้เช่า/การจองรายวัน ไม่มีสาขาในฐานข้อมูล → โหลดบนเครื่องอื่นจะถูกยกไปสาขาแรก · ผู้เช่าห้องชื่อเดียวกันคนละสาขาถูกรวมเป็นคนเดียว · ตรวจสลิปหาบิลด้วยเลขบิลอย่างเดียว (ทั้งสองสาขามี INV-202611-A1 ได้)
- **แก้ (`src/lib/supabase-relational.ts`):**
  - `pruneOrphanRows`: ทำงานเฉพาะในเบราว์เซอร์ (เซิร์ฟเวอร์ไม่ลบอะไรอีก) และลบเฉพาะแถวที่ `property_id` อยู่ในสาขาของผู้ใช้ (`scope` = สาขาที่โหลดไว้) — แถวสาขาอื่น/บัญชีอื่น/ไม่มีสาขา ไม่ถูกลบ · ถ้าตารางยังไม่มีคอลัมน์ property_id ใช้แบบเดิม

  - `collectUnifiedTenants`: ผู้เช่าในห้องจะถูกรวมกับผู้เช่าชื่อเดียวกัน **เฉพาะสาขาเดียวกัน**
  - บันทึก `property_id` ของ tenants / daily_bookings / meter_readings (ส่งเมื่อมีสาขาจริง; ถ้ายังไม่รัน SQL safeUpsert ตัดทิ้งให้)
  - โหลด: สาขาของผู้เช่า = `tenants.property_id` → สาขาของห้องที่อยู่ → ค่าในเครื่อง → สาขาแรก · สาขาของการจองรายวัน = `daily_bookings.property_id` → ค่าในเครื่อง → สาขาแรก (helper `branchOf`)

- **ลบ buildings ออกจากโค้ด:** ไม่สร้างแถว buildings / ไม่ส่ง `building_id` ของห้องแล้ว · conflict สำรองของ rooms เป็น `property_id,room_number` · `database.service.ts` ลบห้องจับคู่ด้วย `property_id + room_number` · `payment-slips-server.ts` หาบิลด้วย `invoice_number + property_id` (เดิม join rooms→buildings) · หน้า Database Inspector เอาแท็บอาคารออก
